# StockLens 1.0 멀티 증권사 실계좌 UAT 계획

대상: 키움증권, 토스증권 (KIS 는 0.9 브랜치에서 국내 2회 완료, 미국 본장
야간 러너 진행 중). 자격 증명은 OS keyring 의 정상 제품 흐름
(stocklens-broker verify_and_save)으로만 들어간다. UAT 스크립트는 환경
변수 credential 을 읽지 않고, 요청 헤더·토큰을 출력·저장하지 않는다.

## 사전 조건 (대표 액션)

1. 키움 REST API 앱 키 발급: https://openapi.kiwoom.com (실전 + 모의)
2. 토스증권 Open API 클라이언트 발급: https://corp.tossinvest.com/ko/open-api
   - WTS 설정 > Open API > 허용 IP 에 이 PC 의 공인 IP 등록
3. 각 공급자를 Manager 또는 `stocklens-broker --interactive` 로 연결

## 검사 항목 (공급자 x 시장별)

1. interval 1m/5m/15m/60m/120m/240m 조회 성공 (자동 + 명시 source)
2. 페이지네이션: row_limit 500 으로 다페이지 강제, cursor 진행 확인
3. completed_only=True 에서 미완성 봉 0개
4. 재계산: 1m 원천을 독립 집계해 상위 간격 OHLCV·tail·complete 비교
   (불일치 0 이 통과 기준, 설명 가능한 차이는 문서화)
5. 완료 거래일 캐시: 2회차 조회 cache_hit=True + API 호출 0
6. 세션 경계: KR 09:00~15:30(+마감 동시호가), US 09:30~16:00(+마감 print)
   밖 데이터 미포함
7. 토스 전용: adjusted=false 확인, nextBefore 경계 중복 dedupe,
   허용 IP 미등록 상태에서 ip_not_allowed 안내 확인 (등록 전 1회)
8. 키움 전용: cont-yn/next-key 연속조회, 부호 가격 정규화, cntr_tm
   정렬(공식 HTS 값과 첫 봉·마지막 봉 대조)
9. 라벨-값 계약: 종목·날짜·통화가 요청과 정확히 일치 (전수)
10. 실패 분류: 잘못된 종목 entity_not_found, 잘못된 키 credential_invalid

## 증거 규칙

- `docs/uat/evidence/<provider>/` 에 JSON 저장
- 비밀값·토큰·요청 헤더·계좌 식별자·원본 오류 본문·절대 사용자 경로 금지
- 커밋 전 sentinel 스캔 (tests/test_multi_broker_security_gate.py 원칙)

## 판정

- 공급자별 KR 15 + US 15 = 30/30 완료 (해당 없음 항목은 사유 명시)
- 미해명 데이터 불일치 0
- 캐시·세션·라벨 검사 전부 통과
- 통과 전까지 해당 공급자 capability 는 unverified 유지
