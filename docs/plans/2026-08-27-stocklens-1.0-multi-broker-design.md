# StockLens 1.0 다중 증권사 시세 연결 설계

상태: 승인됨

기준일: 2026-08-27 KST

대상 프로젝트:

- StockLens: `D:\project\stocklens\mcp`
- LeetKit Manager: `D:\project\stocklens\leetkit-manager`

관련 기준 문서:

- `D:\project\stocklens\docs\plans\2026-08-27-broker-market-data-routing-design.md`
- `D:\project\stocklens\docs\plans\2026-08-27-broker-market-data-release-verification.md`

이 문서는 기존 KIS 단독 설계를 KIS, 키움증권, 토스증권의 공통 연결 구조로 확장한다. 기존 설계의 공통 봉 모델, 요청 단위 공급자 고정, 세션 안전 집계, 공급자별 캐시, Manager 연결 수명주기는 유지한다. KIS에 고정된 인증, 상태, 라우팅, Manager UI는 범용 Provider Registry 기반으로 교체한다.

## 1. 출시 목표

KIS, 키움증권, 토스증권의 국내·미국 분봉 연결과 LeetKit Manager의 연결 관리가 모두 완료되고 검증되는 시점을 StockLens 1.0.0으로 정의한다.

정식 1.0.0 출시 전에는 외부 안정 버전으로 기능 일부를 나누어 출시하지 않는다. 통합 검증 중에는 다음 버전만 사용한다.

```text
StockLens 1.0.0rc1, 1.0.0rc2, ...
LeetKit Manager 1.0.0rc1, 1.0.0rc2, ...
```

두 제품은 같은 RC 번호 사용을 권장하되, artifact manifest에 호환 가능한 상대 제품 버전 범위를 별도로 기록한다.

## 2. 제품 원칙

1. 증권사 하나만 연결하면 국내·미국 분봉과 시간봉을 사용할 수 있다.
2. 여러 증권사 연결은 테스트나 예비 선로가 필요한 사용자를 위한 선택 사항이다.
3. 연결된 증권사 중 주 사용 증권사 하나만 실제 자동 요청에 사용한다.
4. 주 사용 증권사는 국내·미국 공통이다.
5. 다른 증권사를 추가 연결해도 주 사용 증권사는 자동 변경되지 않는다.
6. 장애가 발생해도 다른 증권사로 자동 전환하지 않는다.
7. 사용자가 명시적으로 전환하거나 `source`를 지정할 때만 데이터 출처가 바뀐다.
8. 한 요청 안에서 서로 다른 공급자의 봉을 섞지 않는다.
9. 주문, 계좌, 잔고, 체결, 주문 비밀번호를 다루지 않는다.
10. 기존 Naver·Yahoo 일·주·월봉 경로와 기존 도구 계약을 보존한다.

## 5. Provider Registry

증권사 정의는 코드에 고정하며 외부 설정 파일이나 사용자 입력으로 만들지 않는다.

```python
@dataclass(frozen=True)
class ProviderDescriptor:
    provider_id: str
    display_name: str
    allowed_hosts: tuple[str, ...]
    allowed_paths: tuple[str, ...]
    credential_schema: tuple[CredentialField, ...]
    supported_profiles: tuple[str, ...]
    signup_url: str
    docs_url: str
    auth_factory: Callable[..., BrokerAuthAdapter]
    provider_factory: Callable[..., MarketDataProvider]
    capability_probe_factory: Callable[..., CapabilityProbe]
```

등록 공급자:

```text
kis
kiwoom
toss
```

Manager, CLI, doctor, 라우터는 각자 공급자 목록을 복제하지 않고 레지스트리 또는 레지스트리에서 생성된 안전한 descriptor 계약을 사용한다.

## 6. 증권사별 입력 계약

### 6.1 KIS

- `app_key`
- `app_secret`
- `real|demo`

### 6.2 키움

- `app_key`
- `secret_key`
- `real|demo`, 실제 기능은 프로필별 probe 결과로 제한

### 6.3 토스

- `client_id`
- `client_secret`
- 첫 출시에서는 검증된 실전 프로필만 노출
- 허용 IP는 저장하지 않고 공식 설정 화면과 오류 안내만 제공

계좌번호와 주문 관련 값은 어떤 공급자 descriptor에도 정의하지 않는다.

## 7. 공통 어댑터 계약

```python
class BrokerAuthAdapter(Protocol):
    provider_id: str

    async def verify(
        self,
        credentials: SecretPayload,
        profile: str,
    ) -> VerificationResult: ...

    async def issue_token(
        self,
        credentials: SecretPayload,
        profile: str,
    ) -> AccessToken: ...


class MarketDataProvider(Protocol):
    provider_id: str

    async def capabilities(
        self,
        profile: str,
    ) -> ProviderCapabilities: ...

    async def fetch_bars(
        self,
        request: BarRequest,
    ) -> BarDataset: ...
```

증권사 어댑터는 인증, 공식 응답 필드, 페이지네이션, 호출 제한, 거래소 코드와 오류 코드를 담당한다. StockLens 공통 계층은 세션, 완료 봉, 상위 시간봉 집계, 지표, 패턴, 캐시, 출처와 완전성 검증을 담당한다.

## 8. 공급자 구현 범위

### 8.1 KIS

현재 `KisDomesticProvider`, `KisOverseasProvider`, `KisVerifier`, `KisClient`의 외부 동작을 고정한다. 클라이언트 생성과 상태 조회만 레지스트리와 공통 runtime으로 이동한다.

### 8.2 키움

- OAuth 토큰 발급
- 국내 분봉 TR `ka10080`
- 미국 분 차트 TR `usa06011`
- `cont-yn`, `next-key` 연속조회
- 국내·미국 응답의 독립 parser
- 공식 거래소 코드 매핑
- 운영·모의 도메인 분리

첫 버전은 키움의 상위 분봉을 직접 사용하지 않고 1분봉을 StockLens에서 집계한다.

### 8.3 토스

- OAuth Client Credentials
- `GET /api/v1/candles`
- 국내 6자리 코드와 미국 ticker
- `interval=1m`
- 최대 200봉 페이지
- `before`, `nextBefore` 페이지네이션
- `adjusted=false` 명시
- 호출 제한 헤더와 허용 IP 오류 분류

토스 캔들의 시장·세션 범위가 정규장 계약과 일치하는지 실측하기 전에는 capability를 `unverified`로 유지한다.

## 9. 라우팅

지원 source:

```text
auto
kis
kiwoom
toss
naver
yahoo
```

`source=auto`는 주 사용 증권사와 해당 요청의 인증된 capability를 확인한 뒤 요청 전체를 하나의 공급자에 고정한다. 실패하면 다른 증권사나 Naver·Yahoo로 자동 전환하지 않는다.

명시적 공급자 source는 strict 요청이다. 주 사용 증권사가 아니어도 연결되고 인증된 공급자를 사용할 수 있으나 실패 시 대체하지 않는다.

기존 데이터 관계:

- KR 일·주·월: Naver
- US 일·주·월: Yahoo
- KR·US 분·시간: 주 사용 증권사
- legacy 모드: 기존 Naver·Yahoo만 사용

## 10. 연결 상태 v2

```json
{
  "state_version": 2,
  "routing_generation": 8,
  "primary_provider": "kiwoom",
  "data_source_mode": "auto",
  "providers": {
    "kiwoom": {
      "generation": 4,
      "lifecycle": "connected",
      "active_profile": "real",
      "profiles": {
        "real": {
          "credential_ref": "non-secret-reference",
          "verified": true,
          "verified_at": "2026-08-27T18:00:00+09:00",
          "capabilities": {
            "kr_intraday": "available",
            "us_intraday": "available"
          }
        }
      }
    }
  }
}
```

규칙:

- 처음 연결한 공급자만 primary가 된다.
- 추가 연결은 primary를 바꾸지 않는다.
- primary 변경은 별도 action이다.
- routing generation과 provider generation을 분리한다.
- 알 수 없는 상태 필드는 버린다.
- 레지스트리에 없는 provider와 profile은 버린다.
- 손상된 상태는 증권사 호출이 없는 안전 모드로 내린다.
- 비밀값, 토큰, 요청·응답 원문을 상태 파일에 쓰지 않는다.

기존 `active_provider`, `active_profile`, 전역 `capability_results`는 KIS 공급자 상태로 읽는 호환 migration을 제공한다.

## 11. 보안 설계

### 11.1 최소 권한

- 시세 endpoint만 허용한다.
- 주문·계좌 endpoint 코드를 포함하지 않는다.
- API host와 path는 descriptor 허용 목록으로 제한한다.
- HTTPS와 TLS 검증을 강제한다.
- 다른 host로의 redirect를 허용하지 않는다.
- Base URL을 사용자 설정으로 받지 않는다.

### 11.2 비밀값 운반과 저장

- 일반 dict 대신 출력이 차단된 `SecretPayload`를 사용한다.
- credential schema에 없는 필드를 거부한다.
- 비밀값의 원문, 일부, 길이, hash를 출력하지 않는다.
- Manager는 고정 실행 파일을 shell 없이 실행하고 비밀값을 stdin으로만 전달한다.
- 비밀값은 OS keyring에 provider·profile별로 저장한다.
- 토큰은 메모리에만 유지하고 generation 변경 시 폐기한다.

### 11.3 버전 keyring 슬롯

새 키는 기존 활성 키를 덮어쓰지 않고 무작위 `credential_ref` 슬롯에 저장한다. 비밀 없는 pending 작업, 새 슬롯 저장, 상태 pointer 교체, 이전 슬롯 삭제 순서로 처리한다. 중단 시 기존 활성 키를 유지하고 orphan 슬롯은 복구 과정에서 삭제한다.

### 11.4 안전한 연결 해제

연결 해제 전에 provider를 `disabled_pending_cleanup`으로 기록하고 generation을 올린다. 그 뒤 토큰, keyring 슬롯, provider 캐시를 삭제한다. 중간 실패가 나도 해당 provider는 요청에 사용되지 않으며, 삭제 결과를 profile별로 보고하고 다음 실행에서 정리를 재개한다.

### 11.5 출력과 지원 파일

- 원본 HTTP 오류 본문을 출력하지 않는다.
- 정제된 provider code, status, retry time만 외부에 제공한다.
- doctor와 지원 파일은 허용 목록 DTO만 직렬화한다.
- 상태 파일이나 keyring 원문을 지원 파일에 포함하지 않는다.
- provider가 비밀값을 반사하는 응답을 보내도 stdout, stderr, 로그, traceback, cache, metrics에 0건이어야 한다.

### 11.6 Manager 폼

- password 입력과 autocomplete 비활성화
- localStorage 저장 금지
- 성공·실패·취소·창 닫기 모두 DOM과 Python 참조 제거
- 입력값을 오류 화면에 다시 채우지 않음
- 둘러보기·화면 캡처·지원 파일 생성 중 입력 폼 보호
- untrusted message는 `textContent`로만 렌더링

## 12. 캐시

```text
cache/market_data/kis/<profile>/
cache/market_data/kiwoom/<profile>/
cache/market_data/toss/<profile>/
```

캐시에는 정규화된 시장 데이터와 비밀 없는 provenance만 저장한다. API 요청·응답 header, token, credential, 계좌 값, 원본 오류 응답은 저장하지 않는다.

provider 삭제는 레지스트리 ID로 만든 정확한 절대 경로가 캐시 root 내부인지 확인한 뒤 실행한다. 경로 이탈, 심볼릭 링크, 사용자 문자열 기반 삭제를 금지한다.

## 13. Manager UX

첫 진입 문구:

```text
사용 중인 증권사 하나만 연결하면
국내·미국 분봉과 시간봉을 사용할 수 있습니다.

여러 증권사를 연결할 필요는 없습니다.
```

상태 표현:

- `사용 중`
- `연결됨`
- `연결 안 됨, 선택 사항`

처음 연결한 증권사는 자동으로 주 사용 증권사가 된다. 다른 증권사 추가 연결은 낮은 강조도의 `다른 증권사 추가 연결`에서 진입한다.

장애 시 자동으로 선로를 바꾸지 않고 연결된 대안을 표시한다.

```text
키움증권에서 데이터를 가져오지 못했습니다.
데이터 출처를 자동으로 변경하지 않았습니다.

[토스증권으로 전환] [다시 시도]
```

주 사용 증권사 해제 시 다른 연결이 있으면 전환 대상을 먼저 고르게 한다. 다른 연결이 없으면 분봉을 사용할 수 없게 된다는 사실을 확인받는다.

사용자 데이터 모드는 두 개만 노출한다.

- 일반 사용, 권장
- 기본 데이터만 사용

내부 `broker_first` 값은 기존 계약 호환을 위해 유지하지만 검증되지 않은 일봉 우선 기능을 UI에 노출하지 않는다.

## 14. 기능 인증

```text
unverified
testing
available
limited
temporarily_disabled
unsupported
```

코드가 존재하는 것과 사용자에게 활성화하는 것을 분리한다. 실전 UAT와 출시 게이트를 통과한 capability만 Manager와 auto router에서 사용한다.

## 15. 호환 계약

기존 capability는 유지한다.

```text
broker_connection_contract: 1
market_data_router_contract: 1
```

추가 capability:

```text
broker_provider_registry_contract: 1
multi_broker_primary_contract: 1
credential_schema_contract: 1
```

구 Manager는 기존 KIS 기능만 사용한다. 신 Manager는 새 capability가 없으면 키움·토스를 숨긴다. 어느 조합에서도 기존 Naver·Yahoo 도구와 MCP 기본 기능은 계속 동작해야 한다.

## 16. 검증

### 16.1 자동 검증

각 provider에 동일한 conformance suite를 적용한다.

- 인증 성공·실패
- 후보 키 검증과 원자 저장
- 국내·미국 1분봉
- 페이지네이션

- KR 15종목

- 캐시 재조회

증권사 간 exact volume 일치는 요구하지 않는다. 대신 venue, session, adjustment, volume basis를 설명할 수 있어야 하며 같은 결과 안에서 공급자 혼합은 0건이어야 한다.

## 17. 개발·릴리스 격리

KIS 현재 기능 브랜치의 남은 미국 본장 UAT와 설치·롤백 게이트를 먼저 완료하고 기준 커밋을 고정한다. 그 기준에서 다음 별도 브랜치와 worktree를 만든다.

```text
StockLens: feature/provider-registry-kiwoom-toss
Manager: feature/multi-broker-manager
```

1.0.0 기능 개발 브랜치에서 production 배포를 금지한다. 통합 게이트 통과 후 `release/1.0.0-rc` 브랜치를 만들고 `1.0.0rcN` artifact를 생성한다.
