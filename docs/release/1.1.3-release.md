## 담긴 것

- 세 Lens 공통 — Codex CLI·ChatGPT 앱 첫 호출 승인 취소 해결. 두 앱은 MCP 도구를 부르기 전에 승인을 묻고
  (`default_tools_approval_mode`), 주석 없는 우리 도구는 전부 대상이라 첫 호출이 취소됐다(codex exec 재현
  "user cancelled MCP tool call" 4회 연속). `_tool_schema.py` LensFastMCP 가 도구마다 `readOnlyHint` 를 붙이고
  (쓰기 도구는 `write_tools=`, 기동 시 `check_write_tools()`), `setup_claude.py` 가 Codex 설정에
  `default_tools_approval_mode = "auto"` 를 적는다. `_tool_schema.py` 세 벌 동일(공개본 sha256 앞 12자 `cb4596a2aa83`).
  설정 파일을 다시 쓸 때 원래 줄바꿈을 지킨다(`_write_text_keep_newline`).
- 세 Lens 공통 — 활성화·데몬·로그인 안내가 Claude 만 가리키지 않는다("쓰고 계신 AI 앱(Claude·ChatGPT)").
- StockLens
  - `get_disclosure` 전 종목 "공시 없음" 수정 — 네이버 `news_notice.naver` 가 9/17 410 Gone. JSON
    `m.stock.naver.com/api/stock/{code}/disclosure` 로 교체(date=DART 접수일 일치 확인, 시각은 적재시각이라 안 실음).
    이름표 "DART 전자공시" → "거래소 공시(KOSCOM)". 0건 문구에 "재료 없음이 아니다".
  - `get_news`(신설) — 종목 태그 기사(분 단위 시각) + 종목명 뉴스 검색(당일 기사 빠름, 시각은 "약" 근사). 출처별
    부분 실패 표시. 네이버뉴스 라벨 칸이 더 붙는 기사도 시각을 잃지 않는다.
  - `get_move_context`(신설) — 시세·거래량 20일 배수·오늘 기사 시각순·14일 거래소 공시·30일 리포트를 한 번에.
    원인 판정 없음. 실패한 출처는 "없음"이 아니라 "모름".
  - instructions 첫 512자에 질문→도구 표(Codex 는 첫 512자를 중시). 도구 수 70→72.
  - `fetch` 가 첫 조회의 "access violation" OSError 만 한 번 더 시도(대표 PC 17:16 실측, 재현 안 됨).
