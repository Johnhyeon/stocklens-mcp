# 1.1 상세 수급 출시 게이트 증거

브랜치 `feature/advanced-market-evidence`. 기준일 2026-08-28 (KST).

능력 하나를 켜는 것은 고객에게 "이 숫자를 믿어도 된다"고 말하는 일이다.
그래서 게이트는 **독립 근거가 있는 것만** 연다. 어댑터가 자기 계산으로
자기를 검증한 것은 근거로 세지 않는다.

## 게이트 현황

| 공급자 | 능력 | 게이트 | 근거 |
|---|---|---|---|
| kis | kr_investor_flow | **열림** | 아래 §1 |
| kis | kr_short_selling | 닫힘 | UAT 미실행 |
| kis | kr_program_trading | 닫힘 | UAT 미실행 |

| kiwoom | kr_short_selling | 닫힘 | 동일 |
| kiwoom | kr_program_trading | 닫힘 | 동일 |
| kiwoom | kr_credit | 닫힘 | 동일 |
| kiwoom | kr_securities_lending | 닫힘 | 동일 |
| kiwoom | kr_foreign_holding | 닫힘 | 동일 |
| toss | (전부) | 닫힘 | 증거 어댑터 없음. 개발자 모드에서도 미구현 |

닫힌 게이트는 고객에게 `verifying`(검증 중)으로 응답한다. `unsupported`
와 다른 상태다. 못 하는 것이 아니라 아직 확인하지 않은 것이다.

## 1. KIS 투자자 수급 (kr_investor_flow)

증거 파일: `docs/uat/evidence/kis/uat_evidence_flow_kis_20260828.json`
러너: `docs/uat/evidence/common/evidence_uat.py`

프로필 real. 14종목 (1.0 KR UAT 와 같은 목록: 대형주·ETF·ETN·우선주·
외국주 혼합). 종목당 30 거래일. **실패 0.**

러너는 공급자 원본 응답을 직접 받아 **자체 코드로 다시 계산**한다.
어댑터의 파서·검산 함수를 부르지 않는다. 어댑터가 자기를 검증하면
같은 오해를 두 번 하고 통과하기 때문이다.

### 1.1 출처 교차 (가장 강한 근거)

**812건 비교, 불일치 0.**

네이버 수급과 대조했다. 네이버는 증권사 API 와 아무 관련 없는 별개
파이프라인이고 자격 증명도 필요 없다. 두 곳이 자릿수까지 같으면 값이
맞을 뿐 아니라 **라벨이 같은 뜻**이라는 것까지 확인된다. 값만 맞고
뜻이 다른 경우(세션 범위·포함 항목 차이)가 라벨-값 계약이 깨지는
전형적인 자리인데, 내부 검산으로는 그걸 잡을 수 없다.

대조 항목은 외국인·기관계. 실측 예 (005930, 2026-08-27):

| 항목 | KIS | 네이버 |
|---|---|---|
| 외국인 순매매 | 1,381,786 | 1,381,786 |
| 기관계 순매매 | -97,433 | -97,433 |
| 종가 | 266,000 | 266,000 |

### 1.2 응답 내부 산술

**1,260건 검산, 불일치 0.**

KIS 는 구분마다 순매수·매수·매도를 다 주므로 `순매수 = 매수 - 매도`
가 응답 안에서 검산된다. 14종목 × 30행 × 3구분 전부 0 차이.

### 1.3 어댑터 충실도

14종목 각 30행에 대해 어댑터 출력과 러너의 독립 계산이 일치. 어댑터가
원본을 옮기는 과정에서 값을 바꾸지 않는다.

### 1.4 이 게이트가 **덮지 못한 것**

- **individual(개인)**: 네이버가 개인을 주지 않아 §1.1 대상이 아니다.
  §1.2 내부 산술과, 2026-08-27 키움 교차 1건(005930 개인 -3,223,427 이
  키움 `ind_invsr` -3,223,427 과 일치, 금액 -862,106 도 일치)으로만
  검증됐다. 키움 재연결 후 전 종목 교차를 돌리면 이 구멍이 닫힌다.
- **증권사끼리 교차(KIS↔키움)**: 이 환경에 키움 자격 증명이 없어
  실행하지 못했다. 러너는 이 사실을 `cross_provider_status:
  unavailable_second_provider` 로 기록하고 통과로 처리하지 않는다.
- **미정산 전이(잠정→확정)**: 2026-08-28 17:30 KST 시점에 KIS 는 당일
  행까지 이미 확정치로 채워 주고 있었다(개인 1,589,169 = 매수
  4,409,904 − 매도 2,820,735). 장중에 잠정치를 받아 마감 후 확정치로
  바뀌는 것을 같은 날 안에서 관찰하려면 장중 실행이 필요하다.
  어댑터의 미정산 처리 자체는 단위 테스트로 고정돼 있다
  (`tests/test_kis_evidence.py`, 빈 문자열 → `unsettled`).

## 2. 아직 열지 않은 게이트

### 2.1 KIS 수급 압력

어댑터는 실계좌 실측으로 만들었지만 UAT 러너를 만들지 않았다.
프로그램매매는 **장중 시계열**이라 장 마감 후에는 당일 데이터로
검증하기 어렵다(다음 장중 실행 필요). 공매도는 일별이라 언제든
검증 가능하다.

### 2.2 키움 전체

이 환경에 키움 자격 증명이 없다(`CredentialStore.load_active("kiwoom",
"real")` → None). 상태 파일에도 kis 만 connected 로 남아 있다.
키움을 다시 연결하면:

1. 키움 6종 게이트의 UAT 를 돌릴 수 있고,
2. KIS 개인 구분의 교차 검증 구멍(§1.4)도 함께 닫힌다.

**대표 확인 필요 사항이다.** 키움 연결 없이는 1.1 의 절반(대차·신용·
외국인 보유는 키움만 제공)이 계속 닫혀 있다.

## 3. 보안

증거 파일에 자격 증명·헤더·토큰·계좌 식별자·원본 오류 본문이 없다.
문자열 검사로 확인: `appkey`, `appsecret`, `secretkey`, `bearer`,
`authorization`, `token`, `cano` 미포함.

allowlist 에 계좌·잔고·보유·주문 namespace 가 없다는 것을 경로 조각
단위로 검사한다 (`tests/test_evidence_security.py`). 지금 없다는 확인이
아니라, 나중에 endpoint 를 추가할 때 딸려 들어오는 것을 막는 검사다.
