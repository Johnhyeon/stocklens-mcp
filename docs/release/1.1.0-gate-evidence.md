# 1.1 상세 수급 출시 게이트 증거

브랜치 `feature/advanced-market-evidence`. 기준일 2026-08-28 (KST).

능력 하나를 켜는 것은 고객에게 "이 숫자를 믿어도 된다"고 말하는 일이다.
그래서 게이트는 **독립 근거가 있는 것만** 연다. 어댑터가 자기 계산으로
자기를 검증한 것은 근거로 세지 않는다.

와 다른 상태다. 못 하는 것이 아니라 아직 확인하지 않은 것이다.

## 1. 투자자 수급 (kr_investor_flow, KIS·키움)

증거 파일: `docs/uat/evidence/common/uat_evidence_flow_20260828.json`
러너: `docs/uat/evidence/common/evidence_uat.py`

프로필 real. **15종목** (1.0 KR UAT 목록 + 코스닥 대형주 247540).
대형주·ETF·우선주·외국주·코스닥 혼합. 종목당 30 거래일. **실패 0.**
`--symbols` 로 목록보다 많이 요청하면 러너가 거절한다 - 15개를
요청했는데 14개만 돌고 성공으로 끝나면 증거 수치를 믿고 게이트를
열게 된다.

러너는 공급자 원본 응답을 직접 받아 **자체 코드로 다시 계산**한다.
어댑터의 파서·검산 함수를 부르지 않는다. 어댑터가 자기를 검증하면
같은 오해를 두 번 하고 통과하기 때문이다.

### 먼저 읽을 것 - 이 UAT 가 잡아낸 이름표 오류

처음 돌렸을 때 KIS 와 키움의 `foreign` 이 361건 어긋났다. 개인·기관계는
전부 일치했고 외국인만 어긋났으며, 차이는 몇 십~몇 천 주 수준이었다.
시장 현상으로 읽으면 "증권사마다 집계가 조금 다른가 보다" 로 넘어갈
크기다. **데이터가 아니라 이름표 문제였다.**

4종목 32건 대조로 확정:

    KIS frgn_ntby_qty == 키움 frgnr_invsr + natfor   (32/32)

키움은 외국인을 `frgnr_invsr`(외국인)과 `natfor`(내외국인)으로 나눠
주고, KRX·KIS·네이버가 "외국인"이라 부르는 것은 **둘의 합**이다.
어댑터가 좁은 쪽을 `foreign` 이라는 같은 이름으로 내보내고 있었다.

고친 뒤: 키움에서 `foreign_registered`(좁은 쪽)와 `domestic_foreign`
을 그대로 두고, `foreign` 은 둘의 합으로 파생한다. `raw_categories` 에
`frgnr_invsr+natfor` 로 출처를 기록한다. 5주체 합 검산은 파생 합계를
쓰지 않는다 (내외국인을 두 번 세게 된다).
계약 테스트 `tests/test_foreign_category_contract.py`.

**이 오류를 잡은 것이 교차 검증의 값어치다.** 내부 산술 검산만 했다면
양쪽 다 자기 응답 안에서는 완벽히 일관돼 통과했을 것이다.

### 1.1 출처 교차 (가장 강한 근거)

**증권사 교차(KIS↔키움) 1,350건 비교, 불일치 0.**
개인·외국인·기관계 3구분 × 15종목 × 30일 전부 자릿수까지 일치.

**네이버 교차 900건 비교, 불일치 0.**

네이버 수급과도 대조했다. 네이버는 증권사 API 와 아무 관련 없는 별개
파이프라인이고 자격 증명도 필요 없다. 두 곳이 자릿수까지 같으면 값이
맞을 뿐 아니라 **라벨이 같은 뜻**이라는 것까지 확인된다. 값만 맞고
뜻이 다른 경우(세션 범위·포함 항목 차이)가 라벨-값 계약이 깨지는
전형적인 자리인데, 내부 검산으로는 그걸 잡을 수 없다.

대조 항목은 외국인·기관계. 실측 예 (005930, 2026-08-27):

| 항목 | KIS | 네이버 |
|---|---|---|
| 외국인 순매매 | 1,381,786 | 1,381,786 |
| 기관계 순매매 | -97,433 | -97,433 |
| 종가 | 266,000 | 266,000 |

### 1.2 응답 내부 산술

**1,350건 검산, 불일치 0.**

KIS 는 구분마다 순매수·매수·매도를 다 주므로 `순매수 = 매수 - 매도`
가 응답 안에서 검산된다. 15종목 × 30행 × 3구분 전부 0 차이.

### 1.3 어댑터 충실도와 공개 경로

15종목 각 30행에 대해 어댑터 출력과 러너의 독립 계산이 일치. 어댑터가
원본을 옮기는 과정에서 값을 바꾸지 않는다.

**공개 도구의 배치 경로도 실제로 밟는다.** 서비스만 검증하고 도구를
안 밟으면 도구에서만 나는 오류(직렬화·인자 검증·응답 모양)를 못
잡는다. 실제로 이 검사가 배치 응답 모양 문제를 하나 잡았다.

증거 JSON 에는 프로필·endpoint(경로·TR ID·페이지네이션 여부·행
수)·공급자별 미지원 항목이 사례마다 기록된다. 무엇을 어떤 자격으로
어디서 받았고 무엇이 검증 대상이 아니었는지 남기기 위해서다.

### 1.4 이 게이트가 **덮지 못한 것**

- **미정산 전이(잠정→확정) 실측**: 이 UAT 를 돌린 2026-08-28 18:50 KST
  시점에 KIS 는 당일 행까지 이미 확정치로 채워 주고 있었다(개인
  1,589,169 = 매수 4,409,904 − 매도 2,820,735). 장중에 잠정치를 받아
  마감 후 확정치로 바뀌는 것을 관찰하려면 **장중 실행이 필요하다.**
  러너 `--phase intraday` 가 종목별 스냅샷(값 + 정산 여부)을 남기고,
  마감 후 `--phase final` 실행이 그 스냅샷과 대조한다. 확인 항목은
  날짜 키 유지·미정산에서 정산으로의 전이 수·이미 정산된 값의 무단
  변경이며, 결과는 증거 JSON 의 `provisional_transition` 에 남는다.
  증거 JSON 은 `state` 와 함께 **`verified`** 를 적는다. `state` 만
  보면 대조는 했는데 전이가 0건인 실행("이미 확정된 값을 두 번 읽음")도
  `checked` 라서 검증한 것으로 읽힌다. `verified` 는 관측된 전이가
  1건 이상일 때만 참이다.

  **게이트용 실행은 `--require-transition` 으로 돌린다.** 그 플래그가
  있으면 전이를 확인하지 못한 실행이 **종료코드 1** 로 끝난다. 없이
  돌리면 평상시 확인이라 통과한다. 네 경로 모두 실측했다:
  스냅샷 없음+require=1, 스냅샷 저장=0, 대조했지만 전이 0건+require=1,
  require 없음=0.

  현재 저장된 증거는 `verified: false` 다. **이 파일은 전이 검증의
  근거가 아니다.** 다음 거래일 장중에 `--phase intraday` 를 돌리고
  마감 후 `--require-transition` 으로 다시 돌려야 채워진다.
  지금 대신 고정돼 있는 것: 어댑터의 미정산 처리 단위 테스트
  (`tests/test_kis_evidence.py`, 빈 문자열 → `unsettled`;
  `tests/test_kiwoom_evidence.py`, 검산 깨진 0 → `unsettled`)와
  캐시의 잠정값 배제·확정 교체 계약(`tests/test_evidence_cache.py`).
- **AI 편향 질문 쌍**: 도구 응답은 질문 문구를 입력으로 받지 않으므로
  같은 인자면 같은 값이 나온다. 편향이 생길 수 있는 자리는 해석
  단계이고, 그걸 막는 필드(`data_state`·`unavailable_reason`·`unit`·
  `granularity`)는 응답에 들어 있다. 사람이 읽는 검증은 아직 안 했다.

## 2. 아직 열지 않은 게이트

### 2.1 KIS 수급 압력

어댑터는 실계좌 실측으로 만들었지만 UAT 러너를 만들지 않았다.
프로그램매매는 **장중 시계열**이라 장 마감 후에는 당일 데이터로
검증하기 어렵다(다음 장중 실행 필요). 공매도는 일별이라 언제든
검증 가능하다.

### 2.2 키움 수급 압력 5종

프로그램매매·공매도·신용·대차·외국인 보유. 어댑터와 단위 테스트는
있지만 실계좌 UAT 러너를 만들지 않았다. 대차·신용·외국인 보유는
키움만 제공하므로 교차 출처가 없다 - 어떤 독립 근거로 검증할지
먼저 정해야 한다.

### 2.3 UAT 홈 주의

이 UAT 는 `STOCKLENS_HOME=D:\project\stocklens\.uat-home-1.0` 에서
돌려야 한다. 기본 홈(프로덕션)에는 KIS 만 연결돼 있어 증권사 교차가
빈 채로 돈다. 러너는 그 경우 `cross_provider_status:
unavailable_second_provider` 로 기록하고 통과로 처리하지 않는다.

## 3. 보안

증거 파일에 자격 증명·헤더·토큰·계좌 식별자·원본 오류 본문이 없다.
문자열 검사로 확인: `appkey`, `appsecret`, `secretkey`, `bearer`,
`authorization`, `token`, `cano` 미포함.

allowlist 에 계좌·잔고·보유·주문 namespace 가 없다는 것을 경로 조각
단위로 검사한다 (`tests/test_evidence_security.py`). 지금 없다는 확인이
아니라, 나중에 endpoint 를 추가할 때 딸려 들어오는 것을 막는 검사다.
