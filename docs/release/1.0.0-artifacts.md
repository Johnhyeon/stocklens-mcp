## rc1 이후 달라진 것

rc1 검증(2026-08-28) 뒤에 두 가지가 얹혔다. **rc1 의 산출물 해시와 검증
증거는 이 릴리스에 그대로 쓸 수 없다.** 다시 빌드하고 다시 검증했다.

1. **네이버 화면 개편 대응.** 국내 도구가 전부 멈춰서 HTML 파싱을 JSON API
   로 전환했다. 개인 순매매가 새로 들어왔고, get_stock_sector 캐시 TTL 을
   실효값이던 300/3600 으로 되돌렸다.
2. **1.1 상세 수급 병합.** `feature/advanced-market-evidence` 는 rc1 위에
   바로 얹혀 있어 궤적 모델·실행 컨텍스트 같은 다른 작업은 딸려 오지 않는다.
   공개 도구 2종이 늘어 66 → 68 개가 됐다.

0.9.1 은 따로 내지 않았다. 같은 판에 1.0.0 이 나가므로 PyPI 에 버전을 둘
올릴 이유가 없고, 패치노트도 한 절로 합쳤다.

## 키움 단독 흐름 2건을 확인하지 못했다

`rc1_single_broker.py` 의 키움 KR·US 분봉이 `credential_invalid (http=200)`
로 실패했다. 릴리스 판단 근거를 남긴다.

**원인은 코드가 아니다.** 셋으로 확인했다.

1. 같은 홈·같은 키로 **1.1 병합 전 코드(rc1)** 를 돌려도 똑같이 실패한다.
   1.1 이 키움 클라이언트를 건드렸으므로(토큰 저장소) 이 대조가 필요했다.
2. `http=200` 이다. 키움 서버가 정상 응답하면서 키를 거절한 것이다. 우리가
   호출을 못 한 게 아니다.
3. 같은 라우팅·집계 경로를 쓰는 KIS 는 같은 시각에 KR·US 모두 통과했다
   (rows=30, `broker_connected_and_intraday_supported`).

**실제 원인**: 키움 키는 발급 시 등록한 IP 에서만 동작한다. 검증 시점에
대표가 일본에 있어 등록 IP 와 달랐다. 계정·코드 문제가 아니다.

**분봉 경로는 UAT 통과본 그대로다.** 키움 UAT(2026-08-28) 이후 이 릴리스
까지 `kiwoom_domestic.py` · `kiwoom_overseas.py` · `router.py` ·
`resample.py` · `broker_http.py` 는 **한 줄도 바뀌지 않았다**. 바뀐 것은
`kiwoom_client.py` 의 토큰 저장소 34줄과 새 파일 `kiwoom_evidence.py`
(상세 수급, 분봉과 다른 경로)뿐이다. 토큰 저장소는 KIS 가 같은 코드로
오늘 통과시켰다.

**남은 위험**: 키움 전용 토큰 저장소 배선을 이 빌드에서 키움으로 직접
확인하지 못했다. 대칭 코드이고 KIS 쪽이 통과했으므로 낮다고 보고 출시한다.
등록 IP 에서 접속 가능해지는 대로 `rc1_single_broker.py` 를 다시 돌려
8/8 을 채우고 이 절을 갱신할 것.

## 아직 열지 않은 것

프로그램매매·공매도·신용·대차·외국인 보유는 어댑터만 있고 실계좌 UAT 를
돌리지 않아 `_RELEASE_VERIFIED` 에서 전부 닫혀 있다. 호출하면 `unverified`
+ `release_gate_closed` 로 답한다. 설치본 MCP 실호출에서 닫힌 채로 응답하는
것을 확인했다. 고객에게 나가는 글(메일·패치노트·가이드)에서도 이 항목은
광고하지 않고, 가이드에는 "API 키 문제가 아니다"라고 적었다.
