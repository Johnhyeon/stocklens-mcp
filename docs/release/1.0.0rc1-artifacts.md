## 시각 검수와 재검증 반영 (2026-08-28)

설치본 검수와 재검증에서 결함 셋을 잡아 고치고 이 절차를 다시 돌렸다.

1. 연결 창이 공급자 목록을 받기 전에 먼저 떠서, 그 사이 숨겨야 할
   증권사 탭이 잠깐 보였다. KIS 외 탭을 기본 숨김으로 바꿨다.
2. 상태 파일은 "연결됨"인데 자격 증명을 읽지 못하면 분봉 조회가
   `KeyError` 로 죽었다. 구조화된 오류(`not_configured`)로 바꾸고
   "다시 연결" 안내를 붙였다. 키가 틀린 것과 구분해서 말한다.
3. 검증기가 stdout 만 UTF-8 로 감싸 argparse 안내(stderr)가 깨졌다.
   stderr 도 감쌌고, 자식 출력에 대체 문자가 나오면 검증을 실패시킨다.

앱 내 가이드도 현재 화면에 맞게 고쳤다 (2사 지원, 하나면 충분,
물음표 안내 단계 신설, 사용 방식 라벨).

재실행 결과: StockLens 1,107 통과 / Manager 688 통과, 재빌드 후
깨끗한 venv 재설치, 스모크 16/16, 단독 연결 흐름 8/8, 롤백 리허설 성공.

### 알려진 제약: KIS 토큰 발급 1분 1회

두 검증기를 연달아 돌리면 KIS 가 `rate_limited` 를 돌려준다. 토큰
발급 엔드포인트가 1분 1회 제한이고, 이 빌드의 토큰은 프로세스
메모리에만 살기 때문이다. 검증기 사이에 70초를 두고 받은 것이 위
증거다. 프로세스 간 토큰 재사용은 1.1 작업 브랜치에 구현돼 있으며
이 RC 에는 들어 있지 않다.

## 이전 후보 (superseded, 사용 금지)

2026-08-28 첫 rc1 빌드의 **sdist 두 개**를 배포물 오염으로 폐기했다.
Manager sdist 에 과거 빌드 산출물 `dist_exe_new/LeetKitManager.exe`(19MB)와
테스트·내부 문서가, StockLens sdist 에 UAT 원본·설계 문서·프로토타입
이미지가 들어 있었다. 아래 해시를 가진 파일은 쓰지 않는다.

| 파일 | 폐기된 SHA-256 |
|---|---|
| `stocklens_mcp-1.0.0rc1.tar.gz` | `8716cb2f29461fda2d3229a505651db883507975d1e31c60dcd88a5ab1ea3518` |
| `leetkit_manager-1.0.0rc1.tar.gz` | `575e61d8b8e92c579f329692ac89a8f3c662e985406c6527d5aa022711159b16` |

**wheel 두 개는 바뀌지 않았다.** 오염은 sdist 제외 목록 문제였고 wheel 은
패키지 디렉터리만 담기 때문이다. 위 표의 wheel 해시는 첫 빌드와 동일하며
그대로 유효하다.

수정 내용: 두 pyproject 의 sdist 제외 목록 정비 (Manager 는 제외 설정
자체가 없었다). 결과 크기 Manager sdist 22.0MB -> 1.97MB,
StockLens sdist 0.64MB -> 0.42MB. 오염 후보 0건으로 재확인했다.

## 설치본 검증 결과

깨끗한 venv 에 두 wheel 을 설치해 재실행했다 (코드페이지 949 환경).

```
python docs/release/rc1_smoke.py --venv <venv> --home <STOCKLENS_HOME>
python docs/release/rc1_single_broker.py --venv <venv> --home <STOCKLENS_HOME>
```

- 스모크 16개 항목 통과, 실패 0
- 증권사 하나만 연결한 흐름 8개 항목 통과, 실패 0. KIS 단독·키움 단독
  각각 국내와 미국 분봉을 그 증권사에서 받는다.
- 롤백 리허설: 0.9.0/0.3.2 로 내렸다가 rc1 로 복귀 성공

검증기는 venv 와 홈 경로를 인자(`--venv`, `--home`) 또는 환경변수
(`RC1_VENV`, `RC1_STOCKLENS_HOME`)로 받는다. 임시 폴더를 하드코딩하면
그 폴더가 지워졌을 때 증거를 재현할 수 없다.

자식 프로세스 환경에 `PYTHONIOENCODING=utf-8` 을 지정한다. 이게 없으면
코드페이지 949 환경에서 한국어 출력이 CP949 로 나와 검증기가
UnicodeDecodeError 로 멈춘다 (2026-08-28 재현).
